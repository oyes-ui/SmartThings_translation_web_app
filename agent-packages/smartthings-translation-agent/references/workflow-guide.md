# 번역·검수 업무 가이드

이 문서는 사람과 에이전트가 함께 사용하는 업무 안내의 정본입니다. 하고 싶은 일을 자연어로 설명하면 에이전트가 필요한 도구와 내부 설정을 구성합니다. 사용자가 JSON을 작성할 필요는 없습니다. 이미 끝낸 단계와 불필요한 단계는 생략합니다.

## 업무별 시작점

| 업무 | 필요한 입력 · 자연어 요청 예시 | 진행 · 사용자 판단 | 산출물 · 다음 작업 |
| --- | --- | --- | --- |
| 한국어 원문 개선·양식 정리 | 원문, 기준 양식. “이 초안을 다듬고 기존 양식에 넣어줘” | 원문 확인 → 개선안 → 승인된 문안의 양식 변환·용어집 하이라이트. 문안과 양식 정본을 확인 | 개선안·Excel 수정본 → 한국어 승인 후 영어 번역 |
| 새 용어집 반영 | 용어집 파일, Google Sheets 대상 탭. “승인한 용어집을 시트와 기본값에 반영해줘” | Drive/Sheets 스킬로 변경안 확인·승인 → 시트 업데이트 → 승인 CSV를 앱 DB에 반영 → 기본 CSV 검증·교체 | 동기화 결과·기본 CSV → 새 작업부터 사용. 기존 작업 설정 유지 |
| 영어·다국어 초벌 | 워크북, 대상 언어, 기준 원문. “이 파일을 독일어와 일본어 초벌로 만들어줘” | 원문 그룹 확인 → 과잉 매칭·대문자 리스크와 용어집 적용·제외안 확정 → Gemini 번역·Excel 기입·하이라이트 | 초벌 Excel → 에이전트 검수. 유료 API 범위와 용어집 설정은 사용자 확정 |
| 번역 검수·승인안 | 번역본, 용어집, 저장 폴더. “셀과 시트를 검수하고 옵시디언 승인표까지 만들어줘” | 셀 검수 → 시트 일관성 검수 → 리드 통합 → 문서 생성. 승인표를 위한 추가 재검수 없음 | 파일·언어별 상세 MD, Story·언어별 통합 승인검토표 → 사용자 승인 후 `/st-apply` |
| 확정본 일부 변경 | 기준 파일, 변경 표현·범위. “이 표현만 바꾸고 변경 문자를 빨갛게 표시해줘” | 지정 범위 수정·필요한 재번역 → 승인 문안 반영 → 변경 빨강·용어집 파랑 표시 | 수정본·revision 기록 → 필요 시 해당 범위 검수 또는 납품 |
| 여러 파일에 개별 설정 | 파일 목록, 파일별 언어·용어집·적용 범위. “두 파일을 각각 다른 용어집으로 번역하고 검수해줘” | 파일별 설정 확정 → 필요한 워크북 준비 → 초벌 → 에이전트 검수. 성공한 작업 계속 진행 | 파일별 초벌·상세 MD, 통합 승인표·실패 목록 → 실패 원인 해결 또는 승인 반영 |
| Excel 서식·양식 변경 | 원본, 값·구조·서식 기준 파일. “문안은 유지하고 이 양식으로 맞춰줘” | 기준 확인 → 허용 구조·서식 변경 → 독립 보존 검증 | 검증된 수정본 → 번역·검수 또는 납품 |

## 기본 판단

- 원문 그룹은 US·JA·CN·TW는 KR, 나머지는 승인된 US가 기본입니다. 작업별 기준 원문을 명시해 변경할 수 있습니다.
- 기본 API 실행은 초벌 번역·Excel 기입·하이라이트입니다. API 검수·역번역은 명시 요청 때만 실행합니다. 에이전트 검수는 현재 대화 환경에서 이어갑니다.
- 용어집 활성화·제외안은 사용자 확정 후 사용하며, 번역부터 승인 반영까지 같은 파일별 설정을 전달합니다.
- 중단된 유료 호출을 자동 재시도하지 않습니다. 실패·미완료는 승인표에 표시하며 정상적으로 제안이 없는 완료와 구분합니다.
- 실제 수정은 사용자 승인 후 `/st-apply`로 반영합니다. 승인표 생성은 승인 자체가 아닙니다.
- Obsidian 저장 위치가 정해져 있으면 바로 저장하고, 없으면 위치만 확인합니다. 기존 사용자 메모는 보존합니다.

## 기능과 지원 범위

공용 명칭은 **워크북 준비, 작업별 용어집 설정, 다중 워크북 번역, 에이전트 검수, 승인검토표 생성, 선택 수정·검수 표시, 서식·양식 변환**입니다. CO는 기존 사례·호환 진입점의 이름입니다.

기존 한국어 원문 정리·부분 수정·검수 도구는 그대로 사용합니다. 범용 설정→초벌→검수→승인표 연결은 `workbook_batch.py`로 지원합니다. 합성 Excel·가짜 API로 검증했으며 실제 유료 번역은 실행하지 않았습니다. 검수 실행은 활성 에이전트가 이어가며 터미널 도구만 실행해 놓으면 모델 검수가 저절로 수행되지는 않습니다. 새 시트 복제에서 보존할 수 없는 차트·이미지·주석 상자 등은 사전에 거부합니다. Google Sheets 편집은 별도 Drive/Sheets 스킬이 수행하며 이 패키지가 원격 시트를 자동 추측해 변경하지 않습니다.

## 실행 도구와 저장 형식

에이전트는 [범용 작업 설정·재개 규약](workbook-batch.md)에 따라 내부 설정을 작성합니다. 단일 파일도 같은 경로를 사용합니다. 초벌이 이미 있으면 `translate: false`, 대상 시트가 준비되어 있으면 `prepare`를 생략합니다. 초벌만 요청했다면 `review: false`로 검수를 생략합니다.

상세 MD와 통합 승인표의 자동 생성 영역은 갱신됩니다. 사용자가 작성하는 메모·승인 의견은 문서 아래 **사용자 메모** 영역에 남깁니다. 자동 생성 표시가 없는 기존 문서는 덮어쓰지 않고 충돌을 보고합니다. 승인표 JSON은 파일별 원본 검수 manifest와 후보 식별자를 연결하는 색인이며, 승인된 후보를 해당 manifest에서 처리한 후 `/st-apply`로 넘깁니다.

## 1차 개선 모드

**트리거:** “초벌부터 검수하고 1차 수정본까지”, “번역·검수 후 수정본과 재게이트 문서를 만들어줘”, “1차 개선 모드”. 단순 번역·검수 요청에는 적용하지 않습니다. 새 명령을 만들지 않고 `/st-translate`에서 연결합니다.

**필요한 입력:** 워크북, 기준 원문·대상 언어, 확정한 용어집 적용 범위, 결과 저장 위치. 대화에 있는 설정과 승인을 재사용하고 빠진 판단만 확인합니다. 모드를 명시적으로 요청하면 지정 범위의 1차 수정본 생성까지 승인한 것으로 기록합니다. Gemini 사용·비용 범위와 용어집 적용안은 기존 승인 규칙을 따르며, 이 요청을 최종 납품 승인으로 취급하지 않습니다.

**진행:** Gemini 초벌·Excel 기입·하이라이트 → 활성 에이전트 셀 검수 → 시트 검수 → 리드 취합 → 1차 수정본 생성·독립 반영 검증 → 수정내역 재게이트 문서 → 사용자 검토 대기. API 검수·역번역이나 자동 재번역 반복을 추가하지 않습니다.

리드가 근거와 최종 문안을 확정한 후보만 지정 범위 안에서 반영합니다. 의견 충돌·원문 의미 판단 보류·범위 밖 후보는 미해결로 남깁니다. 원본·초벌을 보존하고 기존 계약 실행 경로로 수정 사본을 만듭니다. 사전 승인 범위와 실제 반영 후보를 기록하며 검수 manifest 전체를 일괄 승인하지 않습니다. 검증 실패 결과를 수정 완료로 표시하지 않습니다.

재게이트는 추가 검수 단계가 아니라 사용자 판단용 문서입니다. 원문·초벌·실제 수정문·이유·후보 ID·미해결 항목을 담고 검증된 변경 기록과 수정본 경로를 연결합니다. 기존 제안 승인표를 수정 완료 내역으로 대신하지 않습니다. 수정 후보가 없으면 ‘검수 완료·수정 없음’, 일부 실패가 있으면 성공 범위와 실패 범위를 구분합니다. Obsidian 사용자 메모는 보존합니다. 이후 사용자 검토 결과에 따라 필요한 추가 수정 또는 최종 납품으로 이어갑니다.

**현재 지원 상태:** 자연어 트리거와 작업 범위 안내를 지원합니다. 초벌→에이전트 검수→제안 승인표와 개별 승인 수정 실행기는 기존 기능입니다. 리드 후보의 사전 승인 범위 판별, 1차 수정 실행·재개 기록, 실제 변경 기반 재게이트 문서의 자동 연결은 **연결 예정**입니다. 현재 `workbook_batch.py`의 완료는 이 모드 전체 완료를 의미하지 않습니다. 해당 연결 전에는 기존 검수·승인 반영 절차를 사용하고, 1차 개선 모드가 자동 실행된다고 안내하지 않습니다.
