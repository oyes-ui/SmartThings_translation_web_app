# Excel 저장·납품 강제 보호 — 2026-10-20

010 수정에서 공백 전용 rich-text run 보호를 누락한 일회용 writer가 사용됐다.
Python 재개방만으로는 Excel이 줄바꿈을 제거하고 다음 문장의 글자색을 잘못 상속하는 문제를
발견하지 못했다. 보호를 선택 단계에서 모든 공용 저장의 필수 처리로 이동했다.

## 적용 내용

| 위치 | 강제 조건 |
| --- | --- |
| 공용 저장 함수 | 실제 Workbook만 허용. 전체 시트의 공백 전용 run을 기존 픽스로 합침. 일반 rich-text 조각의 기본 글꼴 명시 |
| 직렬화 | 텍스트 XML의 공백 보존 속성, CR 문자 참조 보장. 다른 ZIP 멤버 내용 보존 |
| 저장 후 검증 | 공백·CR/LF를 포함한 정확한 문자열과 글자별 폰트·색·크기 비교. 다른 검증기가 통과해도 이 검사를 생략할 수 없음 |
| 계약 저장 | 콜백 기록과 별개로 디스크의 승인 계약을 독립 재검증. 검증 중 파일이 바뀌면 중단 |
| 납품·재개 | 원시 XML 위험 run 및 암묵적 글꼴 검사. 계약의 5축 검증 재실행. 조작한 통과 기록으로 납품 불가 |
| 보조 도구 | 27개 스크립트의 직접 저장 31곳을 공용 저장으로 전환 |
| 앱 호출 어댑터 | 번역·검수·하이라이트 실행 문맥에서 앱 내부 Workbook.save도 공용 게이트로 연결. 문맥 종료 시 원래 메서드 복원 |
| 정적 회귀 게이트 | 과거 보조 writer 예외를 제거. 공용 guard의 저장 구현 및 어댑터 연결만 허용. bootstrap의 args.save는 CLI 플래그 |

## 값·구조·서식 정본

표준 수정·납품은 기존 승인 계약의 값·구조·서식 정본을 유지한다. 안전 인코딩만 정규화해
비교하고 원시 출력 XML은 별도로 검사한다. 실제 글자의 색·폰트 변경은 정규화로 숨겨지지 않는다.
로컬 보조 저장은 호출 직전 Workbook의 문안·문자별 서식이 직렬화 후 그대로인지 검증한다.
승인 범위의 의미 검증은 표준 계약 실행기를 이용해야 한다.

이번 작업은 도구와 회귀 테스트를 변경했다. 기존 16개 납품 파일 및 RAG는 수정하지 않았다.

## 검증

- 패키지 테스트 339개와 28개 하위 테스트 통과.
- 공백 삭제, 줄바꿈 손실, 빨강→파랑 변경, 폰트 크기 변경을 주입하면 저장 실패 및 기존 출력 보존.
- 불투명 writer, 검증 후 파일 변조, 가짜 통과 기록, 불안전한 중단 파일의 재개·납품 차단 확인.
- 숨김/비수정 시트, CRLF, 공백만 있는 셀, 반복 저장, 앱 어댑터의 중첩/실패 시 문맥 복원 확인.
- 실제 010 v2의 임시 사본: 26개 시트/945개 텍스트 셀, 공용 저장 전후 5축 차이 0.
- 그 사본을 Microsoft Excel에서 실제 저장한 뒤 945개 셀의 공백·줄바꿈·글자 서식 차이 0.

테스트 실행은 API를 호출하지 않는다. 기존 파일을 읽는 실제 파일 검증도 임시 폴더에만 저장한다.

```bash
python -m pytest tests -q
python scripts/lint_workbook_writers.py
```

이 강제 장치는 이 패키지의 수정·저장·납품 경로에 적용된다. 외부 프로그램에서 독립적으로
작성한 파일은 안전하다고 가정하지 않으며, 이 패키지로 납품할 때 원시 XML 및 계약 검증을 통과해야 한다.
